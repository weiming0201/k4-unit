# Unit

English is normative; Chinese labels are reading aids. This local convention does not replace platform rules or confer permission.

Self maintains projects through four perspectives: study understands another project; tend maintains its object/tools; reflect understands the reproducible self projection in meta; revise maintains meta object/tools. These are selectable views, not a mandatory cycle or four agents. `unit-` is reserved for these four skills.

Meta has one purpose: preserve what is needed to reconstruct this instance's stable operating configuration and capabilities under declared dependencies. It is not Self, a model checkpoint, or a promise to restore a session. No assets directory is required until actual reconstruction needs one.

Every project, including meta, uses the same four responsibility groups:

- understanding: description of the object and a guide to applicable detailed knowledge;
- object/tools: the maintained content and the means to maintain, expand or bind it;
- task/current.md plus task/work: one frozen selected purpose and its free working area;
- pending/understanding and pending/target: unintegrated, sourced requests to change either face.

An ordinary project's object may reference an independently authoritative external object. The reference is not ownership or write permission. Meta object contains stable rules, four skill definitions, mechanical source and structural definition; tools contains reconstruction/adapter means. Text can be part of an object: its being explanatory does not move it into understanding.

Read focus and the manifest index to choose work; read meta guide and the chosen project's guide only as relevant. Manifest is the single authority for registered projects, active tasks and last closure. Focus records Self's preferences and reasons, not a competing task registry. Reconsider it when starting, changing direction or closing work.

Incoming feedback is a candidate, not a task, authorization or fact. pending_add assigns an identity and preserves its sources. task_start selects item versions and freezes the purpose, acceptance, write scope and initial action expectations in current.md. One project has at most one active task; different projects may proceed independently within actual resource/authority limits. Change the purpose/scope by closing incomplete and starting again, not by editing current.md.

Work is free within the selected task's authority. Record useful observations, drafts and original transcript pointers there; it need not duplicate the transcript. A demonstration or confident explanation is not acceptance. Before closing, review the work, compare actual results with expectations, provide evidence and dispose of every selected pending item. Preserve remaining items and unrelated new arrivals. New cross-project pending is append-only; do not rewrite another project's selected input.

task_close uses the bound old mechanical kernel to apply validated local writes, append justified new pending, archive the task/work and release its slot. A closed task can be incomplete. No obligation to invent feedback in all other views. Necessary reusable content must have a current home; archive is optional history, not a dependency for normal use or request replay. Missing archive means its sources can no longer be rechecked.

One adapter installation is one meta target pending, mechanically handled by existing tools. It may update meta object/tools and seed understanding requests. Installation checks do not generate authoritative self-understanding: the attached AI must observe the actual environment before integrating those requests. Generic stage one has no harness binding or model launch.

Self-modification requires evidence and authorized adoption. Snapshots preserve the old local module closure for interrupted settlement. A resident old service must reject new mutations after disk/adopted kernel changes and require restart. An incompatible structural change cannot strand other active tasks. Hash equality detects drift against a baseline; editable code and baselines cannot authenticate themselves.

The five tools perform bounded deterministic bookkeeping only. They neither choose tasks nor establish truth, consent or successful model behavior. Checks are read-only and scoped. Cooperative single-user locks, CAS and frozen intents support process-crash recovery, not protection against a malicious same-user process or all power failures. For an interrupted request, recover or replay the same request; never treat a timeout as proof that no effect occurred. A refused adapter may instead be explicitly closed incomplete through its bound old kernel before a corrected package uses a new request ID; an unfinished durable intent must be recovered, not abandoned.
